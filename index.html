Completing the computer science program at SNHU and building this ePortfolio has helped me identify where my strengths are and where I want to focus professionally. The coursework gave me hands-on experience across the full development stack, and the capstone project pushed me to revisit earlier work and evaluate it against what I know now. Going back through code I wrote in previous semesters and recognizing issues I missed the first time showed me how much my ability to assess and improve software has grown.

In one of my courses I worked on a group project where three of us built a full-stack application together. We divided the work by layer, with one person handling MongoDB and the CRUD operations, another building out the frontend styling and layout, and the third focusing on the backend logic while staying in close communication with the database person. That experience taught me how important it is to coordinate across layers and communicate clearly about how each piece connects, since a change in the database schema or an API response format affects everyone else's work.

Working with data structures and algorithms was a focus during the capstone enhancements. Adding server-side filtering, sorting, and pagination to the Travlr Getaways API required building query logic that handled any combination of parameters without breaking. That meant working with MongoDB operators for range filtering and chaining sort, skip, and limit operations on Mongoose queries to return the right subset of data.

The software engineering and database work during the capstone reinforced how connected the layers of an application are. Fixing schema types, adding validation, implementing error handling, and completing CRUD coverage with a DELETE endpoint all improved the reliability of the application. Changing a single field type in the Mongoose schema required updates to the seed data, the controllers, and the frontend service to keep everything consistent.

Security came up directly during the capstone when I found that the original Travlr code had error handlers referencing undefined variables, which would crash the server and could expose internals to users. Adding try/catch blocks, input validation middleware, and correct HTTP status codes were straightforward fixes, but recognizing why they matter from a security standpoint was the real growth.

The three enhancements in this portfolio all come from the Travlr Getaways application built in CS-465, with each one targeting a different layer. The software design enhancement improved code structure and reliability through validation middleware and proper error handling. The algorithms enhancement added query logic for filtering, sorting, and pagination on the backend with Angular integration on the frontend. The database enhancement corrected schema field types, added Mongoose validators and timestamps, and aligned the seed data. Together they demonstrate the ability to take an existing codebase, identify problems across the full stack, and improve it systematically.
